# v4 Documentation: Weekly Strategic Planning & Matrix Execution

This document details the planning, scope, user experience, and technical design for the fourth version (v4) of the Personal Assistant Agent. It serves as the formal specification and source of truth for the v4 implementation.

---

## 1. Goal / What This Version Proves

v4 transforms the assistant from a daily reactive tracker into a **strategic academic co-pilot**. 

While v1–v3 proved daily calendar integration, live coursework awareness, and long-term completion memory, v4 introduces high-level **weekly planning**, an under-the-hood **Eisenhower Matrix prioritization engine**, and unified daily execution. It proves:
* The assistant can synthesize a multi-day outlook combining **Google Calendar** (timetable, classes, existing commitments), **Google Classroom** (coursework due over the next 7 days), and **v3 SQLite Memory** (unfinished carryovers).
* The assistant can act as a planning co-pilot: rather than guessing blindly, it clarifies blind spots (workload weight, offline goals), proposes an energy-aware schedule, and books focus blocks to Google Calendar upon explicit user confirmation.
* The assistant treats university lectures as **structural anchors** (not to-do chores) and scans for **"Quick Times"** (15–45 min gaps between classes) to capitalize on the compound effect for micro-tasks.
* The assistant unifies morning and evening check-ins around priority quadrants, tracking daily and weekly progress visually with completion bars.

---

## 2. Done Criteria (Scope)

The implementation of v4 is considered complete when the following criteria are met:

1. **7-Day Horizon Synthesis (`/plan`):**
   - Accurately aggregates the upcoming week's classes from Google Calendar and coursework deadlines from Google Classroom.
   - Extracts carried-over unfinished tasks from SQLite memory and evaluates them with the user.
2. **Collaborative Planning Flow:**
   - Asks 1–2 clarifying questions to identify heavy deliverables or offline goals.
   - Generates a draft proposal with proposed focus blocks placed into open calendar slots matching the user's energy preferences.
   - Books focus blocks to Google Calendar only after the user explicitly confirms.
3. **One-Time Preference Onboarding:**
   - Checks if preferences (name, energy hours, hobbies) exist; prompts only on first run or when missing.
   - Allows natural language updates at any time.
4. **Unified Morning Check-in (`/checkin`):**
   - Combines Calendar and Classroom into a single cohesive briefing without artificial data-source silos.
   - Displays classes as the day's timetable backbone.
   - Groups tasks into **Q1** (Must-Do Today), **Q2** (Deep Focus Block), and **Q3** (Quick Wins / Between Classes).
5. **Accountability Evening Follow-up (`/followup`):**
   - Recaps today's Q1 and Q2 commitments.
   - Displays a visual progress bar (e.g., `[ ▓▓▓▓▓▓▓░░░ ] 70%`).
   - Updates finished items to `DONE` and empathetically rolls unfinished items to tomorrow's radar.
6. **Instant Macro View (`/matrix`):**
   - Renders a clean 4-quadrant overview of the week's tasks directly from SQLite with zero AI latency.
7. **Schedule Shift Shortcut:**
   - Allows the user to notify the bot of canceled/shifted classes in natural language, prompting the bot to re-allocate freed time.
8. **Real-World Weekly Cycle:**
   - Validated across at least one real Sunday planning session and consecutive daily check-ins.

---

## 3. Explicitly Out of Scope

To preserve focus and speed:
* **Gmail / Email Integration:** Inbox scanning and email drafting remain deferred to post-deployment updates (v6 and v7).
* **Autonomous Scheduling (No Guesswork):** The bot will never create, edit, or delete calendar events without direct user confirmation.
* **Persistent Cloud Deployment:** Hosting on an always-on remote server belongs to v5. v4 runs locally with the existing scheduler and bot process.
* **Complex Algorithmic Optimization:** No rigid constraint solvers; uses simple calendar gap analysis paired with Gemini's reasoning.

## 4. Architecture & Memory Boundaries

To ensure zero memory overlap and maintain documentation integrity, the system adheres to a strict **4-Tier Separation of Concerns**:

```
┌────────────────────────────────────────────────────────┐
│ 1. External Source of Truth (Google APIs)              │
│    - Calendar owns: Schedule, Lectures, Focus Blocks   │
│    - Classroom owns: Submissions, Deadlines, Details   │
└──────────────────────────┬─────────────────────────────┘
                           │
┌──────────────────────────▼─────────────────────────────┐
│ 2. Task Memory (SQLite: task_status)                   │
│    - Status: NOT_STARTED, IN_PROGRESS, DONE, SKIPPED   │
│    - Priority: Q1, Q2, Q3, Q4                          │
│    - NEVER duplicates class events.                    │
└──────────────────────────┬─────────────────────────────┘
                           │
┌──────────────────────────▼─────────────────────────────┐
│ 3. Profile / Preferences (SQLite: user_preferences)    │
│    - Read-only context lens: name, energy hours,       │
│      downtime hobbies, max focus duration.             │
│    - Loaded into memory on startup; updated in chat.   │
└──────────────────────────┬─────────────────────────────┘
                           │
┌──────────────────────────▼─────────────────────────────┐
│ 4. Session Dialogue (Ephemeral RAM)                    │
│    - Multi-turn state during the active /plan dialogue.│
│    - Cleared immediately upon plan confirmation.       │
└────────────────────────────────────────────────────────┘
```

## 5. Database Schema Updates (`assistant.db`)

### 1. `task_status` Table Extension
* Add `matrix` column:
  ```sql
  ALTER TABLE task_status ADD COLUMN matrix TEXT CHECK(matrix IN ('Q1', 'Q2', 'Q3', 'Q4') OR matrix IS NULL);
  ```
* Expand valid status set:
  ```python
  VALID_STATUSES = {"NOT_STARTED", "IN_PROGRESS", "DONE", "SKIPPED"}
  ```

### 2. `user_preferences` Table
```sql
CREATE TABLE IF NOT EXISTS user_preferences (
    key TEXT PRIMARY KEY,
    value TEXT,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Security Blueprint:
- **No Credentials in DB:** All tokens and keys remain in `.env` and `token.pickle` (gitignored).
- **Parameterized Queries:** 100% parameter binding (`?`) for all queries to eliminate SQL injection risks.

## 6. Conversational UX & Commands

### The Weekly & Daily Rhythm

| Command | Cadence | Purpose | Output Style |
| :--- | :--- | :--- | :--- |
| `/plan` | Sunday evening (or on demand) | Macro strategy & Calendar focus blocking | Collaborative 3-phase dialogue (Clarify ➔ Propose ➔ Confirm) |
| `/checkin` | Every morning (or on demand) | Micro battle plan for today | Classes as structural timetable anchors + Q1, Q2, Q3 tasks |
| `/followup` | Every evening (or on demand) | Accountability & daily closeout | Visual progress bar + one-line status updates + rollover |
| `/matrix` | Anytime on demand | Macro 30,000-ft quadrant status | Instant 4-quadrant layout straight from SQLite |

### Daily Check-in Unified Format:
```markdown
🌅 Good morning Walid!

🏛️ Today's Classes:
09:00 - 11:00 Math Analysis
11:30 - 13:00 Physics Lecture
15:00 - 17:00 Computer Networks Lab

---
🔥 Q1: Must Finish Today
- Submit ML Lab Code (Due 23:59)

🎯 Q2: Deep Work Block
- 17:30 - 19:00 (After classes): Midterm Prep

⚡ Q3: Quick Wins (Between Classes)
- 11:00 - 11:30 (Between Math & Physics): Submit 10-min Survey
---
Total focus time outside classes: ~2 hours.
```

### Evening Follow-up Format:
```markdown
🌙 Good evening Walid! How did today go?

Today's Progress: [ ▓▓▓▓▓▓▓░░░ ] 70% (2/3 goals finished)

- 🔥 Q1: Submit ML Lab Code — Completed?
- 🎯 Q2: Midterm Prep (17:30–19:00) — Completed?
- ⚡ Q3: 10-min Survey — Completed?
```
