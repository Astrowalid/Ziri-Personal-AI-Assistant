# v1 Documentation: Prove the Loop

This document details the first shipped version (v1) of the Personal Assistant Agent. It describes the system as it is actually built and deployed, documenting deviations from the initial plan, execution instructions, and technical design details.

---

## 1. Final Scope (What v1 Does)

v1 establishes the core end-to-end integration loop between the Google Calendar API, a Telegram bot, and an agent built with the Google Agent Development Kit (ADK). 

* **Telegram Bot Interface (`bot.py`)**: A live Telegram bot that accepts natural language messages from the user and forwards them to the agent.
* **ADK Agent (`assistant_agent.py`)**: An agent named "Ziri" configured with access to Google Calendar capabilities.
* **Google Calendar Tools (`calendar_tool.py`)**: Full read/write/edit access to the user's primary Google Calendar:
  * Fetch/list events for any timeframe.
  * Create new events with titles, descriptions, and durations.
  * Find/search existing events using text queries.
  * Update/reschedule/edit details of existing events.
* **Daily Check-in Trigger (`daily_checkin.py` / `scheduler.py`)**: A local cron-like scheduler script that triggers daily check-ins at a configurable time (default `08:00`). It automatically queries the day's events and sends a priority-focused check-in message to the user on Telegram.
* **Statelessness**: Every bot execution run is a clean slate; conversation memory is session-only and uses an `InMemorySessionService`.
* **Chat ID Persistence**: Saves the user's Telegram chat ID to `chat_id.txt` upon `/start` or any user message, allowing the scheduler to locate the recipient for daily check-in notifications.

---

## 2. Deviations from the Initial Plan

* **Expanded Calendar Toolset**: The initial roadmap specified "Google Calendar tool only (read + write)." To make the bot more helpful, we implemented search (`find_calendar_events`) and update (`update_calendar_event`) tools. This allows the agent to reschedule and modify existing events rather than just listing or adding them.
* **Telegram Chat ID Persistence**: To send the daily check-in unprompted, the bot saves the user's chat ID to a local `chat_id.txt` file. The original plan did not specify how the bot would acquire and persist the target chat ID.
* **Model Choice**: Settled on `gemini-3.5-flash-lite` as the primary LLM, balancing performance, tool-calling capability, and speed.
* **No Shared Session Database**: To maintain strict session-only memory limits for v1, the ADK runner uses `InMemorySessionService`.

## 3. How to Run (From a Clean Checkout)

### 1. Prerequisites
* Python 3.10 or higher.
* A Telegram Bot Token (obtained from [@BotFather](https://t.me/BotFather)).
* Google Calendar API OAuth Desktop application credentials saved as `client-calendar-id.json` in the project root.

### 2. Setup environment
Create a virtual environment and install the dependencies:
```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt  # If requirements.txt exists, or manually install dependencies below
```
*Note: Key dependencies include: `google-adk`, `google-genai`, `python-telegram-bot`, `python-dotenv`, and `google-api-python-client`.*

### 3. Configure Environments
Create a `.env` file in the root directory:
```env
GOOGLE_API_KEY=your_gemini_api_key
TELEGRAM_BOT_TOKEN=your_telegram_bot_token
```

### 4. Authenticate Google Calendar
Run the auth script once to generate your local authentication token:
```powershell
python calendar_auth.py
```
This opens a web browser requesting access to your Google Calendar. Upon authorization, a `token.pickle` file will be generated in the root directory.

### 5. Run the Bot
To start the Telegram bot listener:
```powershell
python bot.py
```

### 6. Run the Scheduler
To start the daily check-in scheduler (runs in the background and checks time every 10 seconds):
```powershell
python scheduler.py
```

## 4. How to Test and Verify

### Direct Code Tests (No Telegram needed)
* **Verify Calendar Tools**: Run `python calendar_tool.py` to fetch today's calendar events and create a test event.
* **Verify Agent Logic**: Run `python assistant_agent.py` to trigger local mock agent turns (listing and scheduling test events).

### Interactive Bot Tests (via Telegram)
1. Search for your bot on Telegram and send the `/start` command.
2. Send a query like: `"What do I have scheduled for today?"`
3. Schedule an event: `"Add dentist at 3pm tomorrow"`
4. Reschedule/update an event: `"Change dentist appointment tomorrow to 4pm"` or `"Add description 'bring insurance card' to dentist event"`

### Trigger Check-In Manually (Immediate Test)
To verify the check-in message formatting and Telegram notification dispatch immediately without waiting for `08:00`:
```powershell
python daily_checkin.py
```
*(Requires `chat_id.txt` to have been generated by sending at least one message to the bot first).*

## 5. Technical Decisions Made

* **Gemini Model Choice**: Utilized `gemini-3.5-flash-lite`. This model supports functional tool calling natively, handles prompt instructions reliably, and is fast and cost-effective.
* **Execution Flow**: Since the ADK agent calls are blocking, the Telegram bot runs them using `asyncio.to_thread` to prevent freezing the asynchronous event loop of `python-telegram-bot`.
* **Scheduler Structure**: A lightweight loop in `scheduler.py` sleeps in 10-second increments. This keeps the CPU idle while ensuring the process responds quickly to standard termination signals (Ctrl+C).

---

## 6. Known Limitations

* **Single-User Target**: The `chat_id.txt` file only persists the *most recent* chat ID that interacted with the bot. The scheduler will send check-ins only to this user.
* **Local Scheduler**: The scheduler runs as a persistent local script. If the machine goes to sleep or the script crashes, daily check-ins will stop.
* **Stateless Agent Context**: Because memory is session-based (`InMemorySessionService`), the agent does not remember past days' priorities or conversations once a session concludes.
* **Blocking Tool Execution**: Calendar tools interact directly with the Google Calendar API synchronously. If API requests slow down, it blocks the agent thread execution temporarily.
