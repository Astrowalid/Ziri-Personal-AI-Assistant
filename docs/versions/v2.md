# v2 Documentation: Add Coursework Awareness

This document details the planning, scope, and technical design for the second version (v2) of the Personal Assistant Agent. It serves as the specification and source of truth for the v2 implementation.

---

## 1. Goal / What This Version Proves

v2 introduces coursework awareness by integrating the Google Classroom API. It proves:
* The capability of the agent to interface with multiple independent external data sources (Google Calendar and Google Classroom).
* Dynamic tool routing, where the agent determines which tool(s) to call depending on the user's natural language request.
* Multi-source scheduled reports (daily check-ins combining both calendar events and coursework assignments).

---

## 2. Done Criteria (Scope)

The implementation of v2 is considered complete when the following criteria are met:
* **Classroom Integration in Daily Check-in**: The daily check-in report contains a distinct Classroom section alongside the Calendar section. This section must display real coursework assignments with their live submission status (*submitted* / *not submitted*).
  * *No caching/persistence*: Data must be pulled live from the Google Classroom API each time a check-in is triggered (not cached or remembered from a prior check-in).
* **Natural Language Queries**: The user can ask the agent about academic coursework directly in natural language (e.g., *"what's due this week?"*, *"did I submit the lab report?"*) and get an answer pulled live from the Classroom API.
* **Preservation of v1 Functionality**: The Calendar tool and Calendar behavior from v1 must remain completely unchanged.

---

## 3. Explicitly Out of Scope

To keep the scope focused and achievable, the following are explicitly excluded from v2:
* **Syncing Classroom into Calendar**: Writing Classroom assignments into Google Calendar as events (not needed, as due dates already auto-sync separately via the academic Google Workspace account).
* **Persistence / Long-Term Status Tracking**: Any status tracking beyond the Classroom API's native submission status (e.g., tracking "done / working on / not done" or persisting assignment state across days or agent runs). This is part of the long-term memory goal for v3.
* **Unified Data Model**: Merging Classroom and Calendar data into a single, unified data model. They must remain independent data sources.

---

## 4. Technical Design & Architecture

### Tool Architecture
* **Separate Read-Only Tool**: The Classroom tool will be implemented as a new, separate, read-only ADK tool. It will query the Google Classroom API and will not write any data.
* **Independent Tool Dispatch**: The Classroom tool will operate completely independently from the Calendar tool.
* **Agent Decision Logic**: The ADK agent will decide which tool(s) to call based on the user's request (e.g., calling only the Calendar tool for schedule queries, only the Classroom tool for homework queries, or both during the daily check-in flow).

### Authentication Note
* **Separate Workspace Account**: The Google Classroom API requires authentication against the user's academic Google Workspace account.
* **Separation of Credentials**: This account is separate from the account used for Google Calendar in v1. 
* **Action Required**: The developer must ask the user which credential setup to use (e.g., separate OAuth client ID credentials, or configuring a multi-tenant client) before beginning the implementation.

### Formatting and UX Specifications
* **Daily Check-In Layout**: The daily check-in must be formatted as two visually distinct, clearly labeled sections, separated by a blank line. Calendar is presented first, followed by Classroom:
  ```
  📅 Calendar
  [existing v1 event list format]

  📚 Classroom
  - [Course]: [Assignment] — due [date] — [Submitted / Not submitted]
  ```
  *(If there are no pending assignments, display "No pending assignments" in the Classroom section).*
* **Visual Distinction**: Use the distinct emojis (`📅` for Calendar, `📚` for Classroom) and headers. Classroom items must never be interleaved into the Calendar list or mistaken for calendar events.
* **On-Demand Queries**: For any natural language queries regarding Classroom data, the agent's response must explicitly identify the items as coming "from Classroom" rather than presenting them bare or mixed with calendar events.

## 5. How to Run

### 1. Prerequisites
* Google Classroom API enabled in the Google Cloud Console.
* Your academic Google Workspace account registered under the **Test users** section of the GCP project's OAuth Consent Screen.

### 2. Authenticate Google Classroom
Run the authentication script to authorize the academic account:
```powershell
python classroom_auth.py
```
This prints an authorization link. Open the link in your browser, sign in with your academic account, grant permissions, and the credential token `token_classroom.pickle` will be saved to your root directory.

### 3. Run Components
Run the bot listener and scheduler as usual:
```powershell
python bot.py
python scheduler.py
```

---

## 6. How to Test and Verify

### Direct Code Tests (No Telegram needed)
* **Verify Classroom Tool**: Run `python classroom_tool.py` to fetch active courses and coursework directly to your console.
* **Verify Agent Logic**: Run `python assistant_agent.py` to test the agent's ability to dynamic-route queries (e.g., asking about Kotlin homework) and confirm the responses are labeled "from Classroom".

### Trigger Check-In Manually (Immediate Test)
Verify the visual formatting of the check-in and Telegram delivery:
```powershell
python daily_checkin.py
```

## 7. Open Questions & Resolutions

* **Classroom API Scopes**: Resolved. The minimum read-only scopes needed are:
  - `https://www.googleapis.com/auth/classroom.courses.readonly` (to retrieve enrolled courses)
  - `https://www.googleapis.com/auth/classroom.coursework.me.readonly` (to retrieve coursework assignments)
  - `https://www.googleapis.com/auth/classroom.student-submissions.me.readonly` (to retrieve student submission status)
* **Check-In Formatting**: Resolved. The visual split layout (Calendar first, Classroom second, with blank lines and emoji headers) separates them cleanly.
